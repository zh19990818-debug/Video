# 回忆记录 (memory-journal)

帮用户把脑海里的回忆，变成可长期保存、可检索、有温度的文字档案。

## 存放位置

所有回忆保存在项目根目录的 `memories/` 下，一条回忆一个文件：

```
memories/
├── INDEX.md                      # 总索引（每次新增后更新）
└── 2026-11-18-外婆的桂花糕.md     # 日期-标题.md
```

日期取**回忆发生的时间**（不确定时用年份，如 `1998-夏天-老家河边.md`；完全不详用 `未知年份-标题.md`）。

## 单条回忆模板

```markdown
---
title: 外婆的桂花糕
when: 1998-秋        # 回忆发生的时间，可模糊
where: 苏州老宅
people: [外婆, 妈妈]
tags: [家人, 味道, 童年]
mood: 温暖           # 一两个词的情绪
recorded: 2026-11-18  # 记录日期
---

## 回忆
（用户的原话为主，整理成通顺的第一人称叙述）

## 细节
- 感官细节：气味、声音、颜色、天气
- 对话片段：记得的原话

## 此刻的感想
（用户现在回看的感受，可选）
```

## 工作流程

1. **倾听优先**：用户讲述时先完整接住，不打断、不评判。若用户只给了一句话，再引导。
2. **温和追问（最多 2–3 个问题）**，挑最有价值的：
   - 大概是什么时候、在哪里？
   - 当时有谁在？
   - 还记得什么气味、声音、画面或一句话吗？
   - 现在想起来是什么感觉？
   用户不想答就跳过，绝不逼问。
3. **整理成文**：保留用户的措辞和口吻，只做错字、顺序、通顺度的整理。**绝不编造用户没说过的细节**；不确定的地方写进 frontmatter 时留空或标"约"。
4. **写入文件**：按模板创建 `memories/<日期>-<标题>.md`。
5. **更新索引**：在 `memories/INDEX.md` 中按时间顺序追加一行：
   `- [标题](文件名) — 时间 · 地点 · 人物 · #标签`
6. **回报**：告诉用户存在哪、标题是什么，并问一句"要补充或修改什么吗？"

## 语音记录转文字

用户给出录音文件（会议、访谈、口述回忆）时：

1. 确认文件路径；用 `ffmpeg -i` 检查能否读取。
2. 转写：`python3 .claude/skills/memory-journal/scripts/transcribe.py <文件> --lang zh [--model small]`
   - 缺依赖先 `pip install faster-whisper`；首次运行会下载模型（需要网络），长录音或要求更准时用 `--model medium`。
   - 输出带 `[mm:ss]` 时间戳的 `.txt`，原始转写保存到 `memories/audio/`，**保留不改**。
   - 若环境无法安装/下载模型，如实告诉用户，并请用户用手机自带的语音转文字或其他工具生成文本后再发来。
3. 整理：转写常有同音字、断句错误、口头禅。先整理为通顺文本，**拿不准的词标注 `(?)` 并向用户确认**，不要擅自猜测人名、数字、专有名词。
4. 按内容归类：
   - 个人回忆口述 → 走上面"工作流程"，存为回忆文件，frontmatter 加 `source: 语音转写`。
   - 会议/访谈 → 存为 `memories/YYYY-MM-DD-会议-主题.md`，结构：参会人、议题、结论、待办（负责人+时间）、原文摘录；链接到原始转写文件。
5. 更新 `INDEX.md`，并说明转写中不确定的地方。

录音含他人声音与隐私信息，同样只保存在本地。

## 其他操作

- **回顾/检索**：用 Grep/Glob 在 `memories/` 中按人物、地点、标签、年份查找，列出清单并简述；用户选定后再读取全文。
- **补充/修改**：在原文件上编辑，不新建；在文末追加 `> 补充于 YYYY-MM-DD：……`。
- **按主题整理**：如"关于外婆的所有回忆"，汇总成一篇时间线，保存为 `memories/专题-<主题>.md`，原文件保持不动。
- **删除**：只在用户明确要求时删除，并同步更新索引。

## 原则

- **隐私**：回忆是私人内容，只存放在本地 `memories/`，不发送到任何外部服务，不提交到公开仓库（提醒用户必要时把 `memories/` 加入 `.gitignore`）。
- **敏感回忆**（亲人离世、创伤等）：语气放缓，先共情再记录，不追问细节，由用户决定写多少。
- **忠于原意**：宁可朴素，不要华丽辞藻；不加鸡汤式总结。
- **语言**：默认使用用户提问所用的语言（通常为中文）。
